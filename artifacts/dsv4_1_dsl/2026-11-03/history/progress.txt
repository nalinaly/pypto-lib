Critical findings from recipe model calls AND AscendC implementation:
1. Window KV: models/deepseek_v4_1/models/modeling_deepseek.py:1054 uses
   separate Linear, RMSNorm, interleave RoPE, then update_win_kv:1155.
   Writer is custom.kv_compress_epilog_v2, mxfp8_bf16, group 32,
   round_scale=True. The attribute reaches ACLNN and graph converter unchanged.
   op_kernel/kv_compress_epilog_v2_quant_fp8.h:269 builds
   2^ceil(log2(max(amax,1e-4)/448)), stores scale as BF16.
   PyPTO quant.py:192 and kernels/window_norm_rope_publish.cpp instead use
   BF16(max(amax,1e-4)/448), then quantize using that rounded scale.
   DSL samples/attn_prologue uses fixed scale=1 and a 512-byte payload only.
   amax=1 scales: PyPTO 0.002227783203125; recipe 0.00390625; DSL 1.
   Setting recipe round_scale=False is not exact PyPTO equivalence either:
   its baseline divides by FP32 scale before storing scale as BF16.

2. Compressed attention KV: compressor.py:39/100 writes mxfp4_bf16,
   group16, round_scale=True, x_scale=1. Recipe g16 quantizer extracts the
   BF16 maximum exponent and subtracts 0x0100; ordinary normal input gives
   shared power-of-two scale 2^(floor(log2(amax))-2), with separate extreme
   and zero handling. amax=1 gives scale 0.25. PyPTO uses
   BF16(max(amax/6,2^-9)), giving 0.1669921875 for amax=1.
   The recipe g16 Process path does not branch on roundScale.
   Files: kv_compress_epilog_v2_quant_fp4_g16.h:114 and layout_2d.h:202.

3. Cache formats match at the logical codec/width level, not quantizer level:
   window 512 FP8 bytes +16 BF16 scales =544 B;
   compressed 256 packed FP4 bytes +32 BF16 scales =320 B;
   index 64 packed FP4 bytes +4 E8M0 scales =68 B per token.
   Recipe attention uses packed rows; QLI index cache keeps payload/scales
   separate; QSLI packs eight index tokens into a 544-byte record. Source
   layer currently publishes split QLI and combined QSLI caches separately.
   PyPTO commonly uses split attention payload/scale buffers and physical
   selected-row IDs. Recipe passes logical sparse IDs plus page tables to FA.

4. Recipe RoPE calls use interleave (adjacent real/imag), matching PyPTO's
   basis. DSL attention prologue produces INTERLEAVE_HALF; adapt before
   group quantization. Other DSL sample prologues use adjacent interleave.

5. Recipe indexer QW passes softmax_scale = head_dim^-0.5 * n_heads^-0.5,
   matching PyPTO's 1/sqrt(128*32) at the high-level formula. DSL sample QW
   requires an explicit softmax_scale (no default); README example scale
   alone is not evidence of a mandatory semantic mismatch.

6. Recipe mixes its own AscendC writer/HC/gate kernels with torch_npu and
   cann_ops_transformer.ops.ds41 operators. It does not prove that all eight
   DSL guide samples are used unchanged in its whole-model path.
   Current compute_win_cache is not the fused DSL attn_prologue call.
   EP decode uses dispatch/GMM/combine; MegaMoE is used only in prefill.
   External ds41 kernel internals were not available in this checkout;
   exact QLI tie/candidate policy cannot be concluded from caller alone.
   ops/ascendc/docs/custom-npu_quant_lightning_indexer.md describes an older
   A3 INT8 interface, not the V4.1 ds41 MXFP4 interface.

Decision update — user accepts all three window quantization alternatives
and delegates the choice to fit DSL intra-core programming + simpler scheduling.

Select the recipes AscendC window KV quantizer for the first implementation:
- FP8 E4M3FN, group32, BF16 power-of-two scale, 544-byte logical packed row.
- scale = 2^ceil(log2(max(amax,1e-4)/448)); match the reference's operation
  order and FP8 rounding, including zero and boundary cases, in validation.
- All three alternatives can run within one core; quantization does not
  itself determine the scheduler. This choice favors a concrete model-level
  reference and the existing DSL attention consumer's packed cache ABI.
- The numerical reference for this writer must use the selected codec;
  existing PyPTO quantizer bytes are not the acceptance oracle after this change.

Implementation boundary to preserve:
- PyPTO expresses task graph, tensor regions, cache slot ownership and access
  dependencies. simpler dispatches tasks and enforces completion/visibility.
- DSL leaf gets explicit tensor views, row/tile identifiers, valid extents,
  and workspace; performs intra-core computation and returns after stores.
- A window postprocessing task owns whole 512-element KV rows, performs
  RMSNorm/RoPE/quantization/cache publication; no cross-core scale reduction.
- Use adjacent-pair RoPE before quantization. Projection/norm rounding is
  an explicit arithmetic boundary, not an incidental consequence of fusion.
- Duplicate slot writes, ring wrap and padding require explicit ownership;
  a task completion dependency covers payload and scale publication together.
- MIX is one AIC + two AIV participants; local Channels stay within that
  cohort. Move sample-level global barriers and launch block-ID work
  distribution into PyPTO/simpler task dependencies and explicit work IDs.
- Initial ABI can carry BF16 queries and UINT8 packed KV with inline BF16
  scale bytes. Current interop dtype whitelist lacks FP8/FP4/E8M0 and requires
  ND identity layouts; typed FP8 and NZ weight integration remains a concrete
  bridge adaptation item, not an already demonstrated capability.
- Existing DSL MQSMLA consumes these 544-byte original and 320-byte compressed
  rows, but its full sample still has its own metadata/work distribution and
  must be refactored into device-callable leaves before simpler scheduling.

Development sequence:
1. Export and call a row-local DSL window writer from PyPTO; compare payload,
   scale, untouched slots, zero/rounding boundary rows and successive decode steps.
2. Complete a window-only decode layer (layer0); integrate projection,
   attention and output DSL leaves incrementally, retaining permitted existing
   HC/MoE components. Validate an entire layer, not only the quantizer.
3. Add full/reuse C2A and C1A/candidate/reindex paths and Engram; then whole model.
   Compressed/index quantizer edge behavior and TopK tie/candidate contracts
   still need individual inspection; window choice is not a blanket semantic change.
4. Prioritize stable decoding and persistent cache correctness over formal
   performance A/B or maximum fusion in this first version.
